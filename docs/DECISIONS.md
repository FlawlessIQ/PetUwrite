# Clovara Decisions — append-only log

Format: date · decision · why. Never rewrite old entries; reversals get new entries.

- **2026-08** · Pivot from insurance-first to wellness-led platform; insurance becomes the cross-sell. · Direct pet-insurance CAC (~$210, ~30-mo payback) doesn't work; membership CAC pays back in months and converts members to policies at ~zero incremental cost.
- **2026-08** · Clovara operates as an MGU with delegated underwriting on carrier paper; modeled at 22% commission. · Delaware DOI exam evidence (Figo 27.65–30.05%, PetPartners 32.5–38.5%) puts 22% below the verified floor.
- **2026-08** · No purchased vet triage; companion informs and routes, never diagnoses. · VCPR state rules; keeps Clovara out of the care-delivery chain; the margin doesn't need it.
- **2026-08** · Rewards never redeem against premium. · Anti-rebating statutes in ~48 states; redemptions are products/services/rider-copays only (test-asserted).
- **2026-09-22** · Positioning: vision "More good years, together"; product "your pet's plan for life"; pillars Plan · Care · Protect. Retire "lifecycle/platform/wellness" from customer copy. · Customer-centric language; pet-centric principle.
- **2026-09-22** · Trial-only membership ($22.99/mo config, 7-day trial); first Plan reveal visible pre-trial as the hook. · Chosen over free tier; reveal is the ad.
- **2026-09-22** · Insurance offered at the Plan reveal (primary attach moment), one smart default configuration, "adjust" secondary. · Peak emotional moment; tier mazes kill conversion.
- **2026-09-22** · Branded wearable ("CloTag") via white-label partner, in the membership from day one; fitness score core data. Partner requirements: raw data rights + API depth. · The fitness-score↔claims dataset is the actuarial moat; device doubles as loss-control benefit in VAS states.
- **2026-09-22** · Data Covenant: companion + tracker data never used against an individual claim or premium (outside a filed program). · Trust is the brand; decided pre-launch, not retrofitted.
- **2026-09-22** · Web policyholder→membership bridge split by state: free-months offer in VAS states (counsel-gated), standard trial invite elsewhere. · Rebating exposure elsewhere.
- **2026-09-23** · Production build contract SPEC.md adopted: P0 foundations → P1 onboarding/capture → P2 attach UX (mock adapter) → P3 launch moments. Onboarding principle: "onboarding never ends"; no field asked without visible benefit; owner-confirmed extraction with provenance. · Sequenced, testable path from demo to product.
- **2026-09-23** · Living-documents protocol adopted (this file, ROADMAP.md, journey-data.js) maintained by Claude Code as part of definition of done. · Vision and roadmap must stay true as we pivot.
- **2026-09-22** · Outdoor access added as a cat-only lever, with `indoor-outdoor` as the reference and the free-roaming penalty tapering with age. · The popular "outdoor cats live 2–5 years" figure is feral-colony data; in owned cats the cost is real but falls almost entirely on young ones (McDonald 2017 trauma deaths at median 3.0 yr; Kent 2022 found no significant difference past age 1). - **2026-09-22** · Age at neutering recorded for large-breed dogs but deliberately never projected — joint-risk framing only. · Hart 2020 measured joint disorder incidence, not survival; converting one to the other would invent a figure. It is also the one input nobody can act on after the fact.

Breed confidence went 32/6/29 → 57/4/6 published/derived/illustrative; the 6 remaining are cats.

The hosted page is still asserted on for the offer it presents.
- **2026-09-23** · Demo pets are never entitlement-gated; real pets are. · The investor demo must be the whole product rather than a paywalled slice, and demo pets are labelled as such in the switcher so nobody mistakes one for their own account.

- **2026-09-23** · Trial-ending email is triggered by Stripe's `customer.subscription.trial_will_end` rather than a scheduler of ours. · Fires from the same source of truth that decides when the trial actually ends, and there is no cron to drift.
- **2026-09-23** · The Data Covenant states the no-premium-change promise in both directions — never up, and never down as a reward for behaving. · A behaviour discount is the same mechanism as a behaviour penalty, and it is the direction a product like this actually drifts. Closing only one half would leave the promise half made. Test-asserted.
- **2026-09-23** · The Covenant names the filed-programme exception on the page rather than omitting it. · Invariant 5 permits a filed, transparent, opt-in rated programme, so a covenant silent on it would be a promise we already know we might break. Stating it is what makes the rest credible.
- **2026-09-23** · The ask registry is enforced by a test that reads the component source, not just documented. · A declarative table nobody checks is a comment. The test caught diet being asked on the wrong screen within a minute of being written.
- **2026-09-23** · Household membership changes only in a Cloud Function via the Admin SDK; clients have no access to `life_invites` at all. · A client able to write household membership could add itself to any household it could name, and household ids appear in every pet path.
- **2026-09-23** · Joining a household while owning pets is refused rather than merged. · Merging two households of pets has real ways to lose an animal's record; refusing with an explanation is honest, and the merge is a feature to design rather than infer.
- **2026-09-23** · The pet photo is worth zero plan-accuracy points, and says so where it is asked. · Every other ask on the Life surface moves the number; letting a photo move it would make the meter a measure of engagement rather than of what we know about the animal. The meter is the honest part of the product.
- **2026-09-23** · Photos are resized in the browser to 2048px before upload, rather than stored as the original SPEC §4.2 asks for. · A 12MB HEIC costs the owner their data allowance and us storage forever, and 2048px is ample for the body-condition trend the original was being kept for. Logged as a spec divergence rather than done quietly.
- **2026-09-23** · The avatar fallback is the pet's initial, never a stock animal silhouette. · A generic dog standing in for a specific dog is worse than a letter — it is a picture of the wrong animal.
- **2026-09-23** · The avatar square crop is biased up on portrait photos rather than centred. · Owners photograph animals standing; a dead-centre crop of a standing dog is a picture of its chest.
- **2026-09-23** · Demo pets are excluded from all four Phase 1 metrics. · Max, Winston and Luna are demonstrated live to investors; a session that reveals in two seconds and sharpens nothing would report an excellent time-to-reveal and a dismal tier-1 completion rate, and both would be measuring us rather than customers.
- **2026-09-23** · Time-to-reveal is measured from the first onboarding step and the stopwatch is read exactly once. · A returning user reaches an existing pet's reveal in about a second; a stopwatch that kept answering would report that as the product's onboarding speed.
- **2026-09-23** · Onboarding sessions that answered no Tier-1 question stay in the completion denominator. · Dropping them makes the rate permanently 100% and the metric decoration.
- **2026-09-23** · The accuracy distribution keeps one score per visitor — their highest — and scores are emitted per 10-point band rather than per tap. · Otherwise the distribution measures how much someone fiddled with the silhouettes rather than how sharp their plan got.
- **2026-09-23** · Metrics with no data say so ("nobody is 30 days old yet") instead of rendering 0%. · Zero and "not yet knowable" are different, and one of them sends someone looking for a problem that does not exist.
- **2026-09-23** · The annual review is anchored on the pet's birthday, not on the anniversary of the last review. · The journey map — the source of truth for the product journey — says "every birthday her plan is re-drawn"; anniversary-anchoring also drifts later every year somebody answers late, until the yearly ritual lands in a different season than it started.
- **2026-09-23** · No review is due until we have known the pet for a year, whatever their birthday says. · A nine-year-old rescue adopted six days ago has a birthday behind them and no year for us to ask about; "anything change this year?" is a strange way to meet someone's dog.
- **2026-09-23** · The review offers "still true" / "this changed" and routes changes into Sharpen's existing questions rather than rendering its own pickers. · One place renders a question, which is the only way the ask registry can enforce anything; a second set would be the first to drift.
- **2026-09-23** · The healthy-years range is stored at each review. · Today's profile cannot tell us what we believed twelve months ago, so without it the "annual re-projection" is only a data refresh with nothing to re-project against.
- **2026-09-23** · "Not now" dismisses the review for the session only and is never persisted. · A review a year overdue should be offered again on the next visit; persisting the dismissal would mean the yearly ritual quietly stops for anyone who was once busy.
- **2026-09-23** · Pets predating the review get an anchor dated today rather than backdated, and cloud pets have it written back. · Backdating would put a review in front of every existing owner at once; anchoring only in memory would reset the clock on every load, so the review would look built and never once fire.
- **2026-09-23** · `built` on the partner journey map means "real in the demo today", confirmed by Conor; the map is audited against that, not against production-readiness. · The page already said so in its own introduction, and the two readings disagree for moments like Protect Her Now, where the demo shows a real pre-filled quote while the P2 attach flow is still planned.
- **2026-09-23** · The Family Circle's journey copy dropped its "with roles — no more 'did anyone feed the dog?'" claim when the moment was marked built. · Roles exist on the household document but nothing reads them and there is no task assignment, so shipping the moment as built with that copy would have made the map false in the description instead of in the horizon.
- **2026-09-23** · The Annual Re-Projection's journey copy dropped the quoted "'half a healthy year gained.'" · It promises a direction the product does not show — a year on, the range usually falls because the animal is older — and VISION forbids promising longer life.
- **2026-09-23** · P3 launch moments are being built before P2 Protect attach, reversing SPEC's phase order. · Conor's call that Clovara Life can launch without insurance makes P3 launch-critical and P2 not; P2 has no dependants, so nothing is blocked by going second, and the carrier program is still in diligence either way.
- **2026-09-23** · The healthy-years projection is deliberately absent from the shareable cards. · SPEC §6.1 lists photo, name and the line; a range is a claim about one identifiable animal, and on a card built to be posted publicly it becomes a prediction strangers read as a deadline.
- **2026-09-23** · Share cards are drawn on the device and never uploaded. · It is a photograph of somebody's pet, the Data Covenant implies the default, and there is no product reason for the image to touch a server.
- **2026-09-23** · Cancelling the share sheet does not fall back to a download. · A file appearing in Downloads after you deliberately cancelled is alarming, and an AbortError is a decision rather than a failure.
- **2026-09-23** · First-Night Mode's escalation list is always visible, never collapsed, and worded identically in every block. · The surface talks to somebody frightened at 2am; making them expand something to learn whether to ring a vet is the one failure that matters, and varying the wording by hour would imply an urgency difference that does not exist.
- **2026-09-23** · Every First-Night block states what is normal at that hour. · The failure mode of a 2am surface is panic at something ordinary — crying, not eating, a worse second night — and reassurance is only safe when paired with the escalation list.
- **2026-09-23** · First-Night Mode is anchored on `knownSince`, not the birthday. · It is about the first seventy-two hours in a new home, which for a rescue has nothing to do with when they were born.
- **2026-09-23** · The Socialization Passport tells kitten owners their window has already closed, rather than gamifying it like a puppy's. · A cat's sensitive period is roughly 2–7 weeks and is over before most kittens are adopted; presenting it as a race to win would be selling somebody something they never had the chance to enter, and implying they missed it would be untrue and unkind.
- **2026-09-23** · The passport has no streak, no daily target and no countdown that shames. · The failure mode of a gamified checklist is an owner pushing a frightened animal through the last stamps to complete a page, which is the opposite of socialisation.
- **2026-09-23** · Passport stamps are stored as ids, and ids no longer in the content stop counting. · Labels will be rewritten; histories should not be, and a retired stamp that kept counting would slowly fill the passport on its own.
- **2026-09-23** · Vaccine Autopilot has no "overdue" status and never uses the word. · A missing entry is evidence that nobody typed it in, not that a dose was skipped; telling an owner their puppy is unprotected on that evidence would be both wrong and frightening.
- **2026-09-23** · Only core vaccines are scheduled; non-core appear as questions to ask a vet. · Leptospirosis, kennel cough, Lyme and feline leukaemia depend on where somebody lives and how the animal lives, and scheduling them would be recommending for an animal we have never seen.
- **2026-09-23** · Rabies carries a "depends on local law" flag rather than being scheduled universally or omitted. · It is mandated for most US pets and not routinely given in the UK or Ireland outside travel, so either alternative would be wrong for half the audience.
- **2026-09-23** · The schedule stops after the first adult booster. · Later intervals depend on the product used and on local guidance; a date we cannot know should not be displayed as though we know it.
- **2026-09-23** · The toxin screen puts the poison-line numbers and "do not try to make them sick" above the lookup. · Somebody frightened reads the first thing on the page and acts on it; the calculator is the least important element and must not be the first one.
- **2026-09-23** · Toxin risk thresholds are set below the published clinical ones, and every uncertainty escalates upward. · The cost of a false "ring now" is somebody's evening; the cost of a false "monitor" is an animal.
- **2026-09-23** · The toxin screen never issues a clearance — its mildest verdict is "watch closely, this is a guide not a clearance". · An owner who reads "safe" stops watching, and several things on the list show nothing for days.
- **2026-09-23** · Nothing in the product ever tells somebody to make an animal vomit. · It is contraindicated for corrosives and petroleum products, hydrogen peroxide causes its own injuries, and it is a decision for the person on the phone — but people reach for it because the internet told them to.
- **2026-09-23** · The nearest-open-ER lookup ships as a seam with a null provider that states it cannot search. · A Places key is Conor's to obtain, and an empty result list at 2am reads as "there is nowhere open near you".
- **2026-09-23** · The sitter card is assembled server-side and carries only fridge-note fields — never the projection, conditions, owner identity or household id. · It is the one thing in the product that leaves the household without a sign-in, so a leaked link should cost a feeding routine rather than a medical record.
- **2026-09-23** · Sitter tokens are 32 CSPRNG bytes, not the human-readable invite alphabet. · An invite code is read aloud across a kitchen table and must be short; a sitter link is pasted, so it can be long and unguessable instead.
- **2026-09-23** · Expired, revoked and never-existed sitter tokens all return an identical 404. · Distinguishable responses would turn the public endpoint into an oracle for guessing tokens.
- **2026-09-23** · Revoking a link that belongs to another household silently succeeds. · An error saying "that link is not yours" confirms the token is real, which is the thing the endpoint must not reveal.
- **2026-09-23** · Sitter links require an account. · The link has to keep working when the owner's phone is in their pocket, which a signed-out local-only record cannot do.
- **2026-09-23** · Gotcha Day is anchored on `knownSince`, never the birthday, and the card lingers for a week after the day. · A rescue's homecoming and birth date are years apart and the homecoming is the one families mark; a prompt that shows only on the exact day is one most people never see.
- **2026-09-23** · Renewal, Explained does not credit an owner's care, contradicting the journey copy. · The Data Covenant promises premiums do not move on this data "not up, and not down as a reward for behaving"; crediting care would break it in the pleasant direction, which is the direction this kind of product drifts.
- **2026-09-23** · Claims experience stays as a renewal factor while behaviour does not. · Whether a policy was claimed on is a filed rating factor everywhere insurance is sold; how somebody cared for their pet is not one, and must not become one by the back door.
- **2026-09-23** · The renewal screen names what is never in the price — companion, tracker, streaks, score, app usage. · At renewal that sentence is worth more than a discount, and it is what makes the list above it believable.
- **2026-09-23** · Home's "these numbers are simulated" disclosure is rendered from the provider's own `simulated` flag rather than hardcoded. · When a real tracker lands the disclosure must disappear by itself; a hardcoded sentence would be left behind as a lie nobody remembered to delete.
- **2026-09-23** · The simulated provider reports a null device id and null vitals rather than inventing them. · A fake device id makes a fabricated reading look sourced, and an invented resting respiratory rate could be read as reassurance about a heart.
- **2026-09-23** · The attach flow's waiting periods are shown as dates rather than durations. · "14 days" needs arithmetic at the exact moment somebody is deciding whether to buy; a date does not.
- **2026-09-23** · The screen of truth states explicitly when nothing is excluded as pre-existing. · A blank space reads as "nothing is excluded", which is a promise about the future that no policy makes.
- **2026-09-23** · The buy button and the attestation stay disabled until the disclosures are scrolled to the end. · SPEC §5 asks for scroll-to-enable, and an attestation somebody could tick without passing the fraud notice is not evidence of anything.
- **2026-09-23** · The illustrative label is driven by the adapter's `illustrative` flag, not hardcoded in the component. · When filed rates arrive the label must disappear by itself rather than being left behind as a false disclaimer.
- **2026-09-23** · `MockRatingAdapter.canBind` is false and the flow says why. · Binding is gated on the carrier programme per SPEC §5; a flow that silently did nothing at the final step would look broken rather than honest.
- **2026-09-23** · The vet-record extraction stub returns nothing rather than plausible sample candidates. · A fabricated "Rabies, 12 March 2025" put in front of an owner to confirm becomes, once confirmed, indistinguishable from a real record forever after.
- **2026-09-23** · `confirm()` stamps `extracted_confirmed` and never `vet_verified`. · An owner reading a scan and tapping yes is not a veterinary attestation; conflating them would launder a guess into a medical fact.
- **2026-09-23** · Extraction confidence is never rendered to an owner. · A score shown as "94%" invites trusting the high ones without reading them, which is precisely the failure invariant 8 exists to prevent.
- **2026-09-23** · The conversational fallback parses weight and neuter status only, never conditions. · "No history of seizures" contains "seizures"; a regex that guessed would produce confident nonsense with our name on it.
- **2026-09-23** · Both previously-blocked P1 items were built behind flags rather than left unstarted. · Neither was blocked on engineering — the security review and the LLM key gate switching them on, and building against a stub makes them a switch instead of a future project.
- **2026-09-23** · Vaccinations, the socialisation passport and sitter links moved off the Life surface into a Health File. · Stacking every P3 moment onto one page made it 15.6 phone screens for a new puppy; none of those three is time-sensitive, and the reveal's sixty-second promise is worth nothing if it lands somebody in a wall.
- **2026-09-23** · Page length is now asserted as a ceiling (12 screens, any state) plus a convergence target (9.5 once answered), rather than one budget per state. · Four budgets would be a curve fitted to today's numbers; a ceiling stops the next surface being stacked on and the target stops the page being permanently long.
- **2026-09-23** · The Health File route carries its pet id (`#/health/<petId>`). · Without it a bookmark or a cold load opened the file on whichever pet was active, which after a fresh load is a demo pet — somebody else's animal.
- **2026-09-23** · Underlined text controls get a `.text-action` utility that grows the hit area to 36px with a negative margin. · They were rendering at about 22px, which is fine for a mouse and poor for a thumb — and this is a phone product used one-handed while holding an animal.
- **2026-09-23** · The Health File summary is computed from the pet's own stored data, with no denominators and no schedule. · The obvious version imported the passport and vaccine engines, which put 103 socialisation stamps and the whole vaccination schedule into the bundle every signed-out visitor downloads.
- **2026-09-23** · The breed tables stay in the main bundle. · Measured before deciding: 1.1s to a visible plan on throttled 4G. Splitting them means refactoring `project()`, which is risk against the most load-bearing code in the repo for no measured gain.
- **2026-09-24** · The Places key is a browser key, restricted to one API and one referrer, and the lookup runs client-side. · Routing it through a function would put a frightened owner's coordinates in our logs for no benefit — the request reaches Google either way, and one fewer party holding a location is better.
- **2026-09-24** · Places quotas were capped (60/min, 1,000/day) before the key was reachable. · The default daily limit is 75,000, which is roughly $2,400 a day for a key that ships in a public bundle.
- **2026-09-24** · The emergency lookup uses `textQuery: "emergency vet"` with `openNow: true`, not `includedTypes: ['veterinary_care']`. · The type search returned a cattery, a telemedicine office and two closed daytime practices; `openNow` is a field you read rather than a filter you apply.
- **2026-09-24** · Open practices sort above nearer closed ones, with unknown hours in between. · A closed practice two streets away is worse than an open one twenty minutes out, and "we do not know" is not "yes".
- **2026-09-24** · The model key is `LIFE_GEMINI_API_KEY`, separate from the underwriting app's `GEMINI_API_KEY`. · The secret already existed; separate secrets mean neither app's rotation can break the other.
- **2026-09-24** · `gemini-3.5-flash` is pinned, chosen by testing negation handling rather than by version number. · 2.0 does not exist on this endpoint and 2.5 404s; 3.5 correctly returned nothing for "no history of seizures", "the vet ruled out hip dysplasia" and "he does not have diabetes". A model swap must repeat that test.
- **2026-09-24** · Conversational onboarding stays switched off despite the key now existing. · Turning it on sends owner-written text about their pet to Google, which is a processor and Data Covenant question for counsel rather than an engineering one.
- **2026-09-24** · "API key 1" restricted to three Clovara referrers and five Maps APIs, down from unrestricted and 31. · It had no application restriction at all on a billable project. Checked before changing it: no Maps-family API had a single request in 30 days and the key string appears in no code under ~/Development, so nothing could break. Verified after: Places returns 403 with no referrer and 200 with an allowed one.
- **2026-09-24** · The 26 removed APIs were mostly not enabled on the project anyway. · Worth recording so the fix is not remembered as larger than it was — the real exposure was `places.googleapis.com`, which is enabled and billable, and that is the one now closed.
- **2026-09-24** · Household `create` now uses a field allowlist rather than checking three named fields. · An adversarial test created a household carrying its own `entitlement: {status: "active"}` and took a paid membership for nothing: `update` had always forbidden touching entitlement, and `create` had simply never been asked. - **2026-09-24** · `memberIds` and `members` are frozen against client writes entirely. · The previous rule required only that the writer remain a member, which let any household member remove the founder and keep their pets. Invites and joins already run through Cloud Functions on the Admin SDK and the client never writes membership after creation, so freezing both costs nothing.
- **2026-09-24** · An adversarial rules suite (`attack.emulator.test.ts`) is kept alongside the intent-based one. · The existing tests checked that the rules did what I meant; both vulnerabilities were in paths I had not thought to mean anything about.
