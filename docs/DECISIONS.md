# Clovara Decisions — append-only log

Format: date · decision · why. Never rewrite old entries; reversals get new entries.

- **2026-08** · Pivot from insurance-first to wellness-led platform; insurance becomes the cross-sell. · Direct pet-insurance CAC (~$210, ~30-mo payback) doesn't work; membership CAC pays back in months and converts members to policies at ~zero incremental cost.
- **2026-08** · Clovara operates as an MGU with delegated underwriting on carrier paper; modeled at 22% commission. · Delaware DOI exam evidence (Figo 27.65–30.05%, PetPartners 32.5–38.5%) puts 22% below the verified floor.
- **2026-08** · No purchased vet triage; companion informs and routes, never diagnoses. · VCPR state rules; keeps Clovara out of the care-delivery chain; the margin doesn't need it.
- **2026-08** · Rewards never redeem against premium. · Anti-rebating statutes in ~48 states; redemptions are products/services/rider-copays only (test-asserted).
- **2026-09-22** · Positioning: vision "More good years, together"; product "your pet's plan for life"; pillars Plan · Care · Protect. Retire "lifecycle/platform/wellness" from customer copy. · Customer-centric language; pet-centric principle.
- **2026-09-22** · Trial-only membership ($22.99/mo config, 7-day trial); first Plan reveal visible pre-trial as the hook. · Chosen over free tier; reveal is the ad.
- **2026-09-22** · Insurance offered at the Plan reveal (primary attach moment), one smart default configuration, "adjust" secondary. · Peak emotional moment; tier mazes kill conversion.
- **2026-09-22** · Branded wearable ("CloTag") via white-label partner, in the membership from day one; fitness score core data. Partner requirements: raw data rights + API depth. · The fitness-score↔claims dataset is the actuarial moat; device doubles as loss-control benefit in VAS states.
- **2026-09-22** · Data Covenant: companion + tracker data never used against an individual claim or premium (outside a filed program). · Trust is the brand; decided pre-launch, not retrofitted.
- **2026-09-22** · Web policyholder→membership bridge split by state: free-months offer in VAS states (counsel-gated), standard trial invite elsewhere. · Rebating exposure elsewhere.
- **2026-09-23** · Production build contract SPEC.md adopted: P0 foundations → P1 onboarding/capture → P2 attach UX (mock adapter) → P3 launch moments. Onboarding principle: "onboarding never ends"; no field asked without visible benefit; owner-confirmed extraction with provenance. · Sequenced, testable path from demo to product.
- **2026-09-23** · Living-documents protocol adopted (this file, ROADMAP.md, journey-data.js) maintained by Claude Code as part of definition of done. · Vision and roadmap must stay true as we pivot.
- **2026-09-22** · Outdoor access added as a cat-only lever, with `indoor-outdoor` as the reference and the free-roaming penalty tapering with age. · The popular "outdoor cats live 2–5 years" figure is feral-colony data; in owned cats the cost is real but falls almost entirely on young ones (McDonald 2017 trauma deaths at median 3.0 yr; Kent 2022 found no significant difference past age 1). Magnitude and taper are ours and labelled as such.
- **2026-09-22** · Age at neutering recorded for large-breed dogs but deliberately never projected — joint-risk framing only. · Hart 2020 measured joint disorder incidence, not survival; converting one to the other would invent a figure. It is also the one input nobody can act on after the fact.
- **2026-09-22** · All dog baselines anchored to median survival (McMillan 2024 Table S3), replacing life-expectancy-at-age-0 anchors on the last eight. · The two metrics are not interchangeable; LE-at-0 counts puppies that die young and answers a question no owner is asking. Breed confidence went 32/6/29 → 57/4/6 published/derived/illustrative; the 6 remaining are cats.
- **2026-09-23** · Clovara Life auth uses the existing `pet-underwriter-ai` Firebase project (shared user pool) but a separate Firestore namespace. · One Clovara identity across products; the `users/{uid}` collection carries underwriting `userRole`/admin claims and a large reviewed rules block that Life data must not touch.
- **2026-09-23** · The Firebase SDK loads behind a dynamic import, gated on a session hint. · The investor demo runs signed out and must not pay ~46KB gz for auth it never uses; `verify-demo.mjs` asserts zero Firebase chunks on the signed-out path.
- **2026-09-23** · Auth: email link + Google; password sign-in retired. · SPEC §3 "no passwords if avoidable"; the password UI shipped the day before SPEC existed.
- **2026-09-23** · Apple sign-in deferred; tracked in ROADMAP as an external dependency, needed only when a native iOS app ships. · Requires an Apple Developer Program membership, Services ID and signing key; no web value until then.
- **2026-09-23** · One household auto-created per user on first sign-in; family circle (P1) adds members to it. · Households own pets from day one so the P1 family circle is an addition, not a migration.
- **2026-09-23** · Stripe via hosted Checkout + Customer Portal rather than Stripe.js. · Zero new client dependencies and no publishable key; dunning, retries, cancel and pause are Stripe's hosted flows rather than UI we build and maintain.
- **2026-09-23** · Membership is its own Stripe Product from day one, so insurance can be a genuinely separate line later. · Invariant 2 requires premium separate from membership fee in UI, Stripe and receipts — retrofitting that split is how it gets broken.
- **2026-09-23** · Build against the FlawlessIQ sandbox Stripe account (acct_1SI7vTPzjq9wJkU5, test mode) for P0. · **A Clovara-entity Stripe account must replace it before anything goes live to real customers.** Nothing in P0 touches live mode.
- **2026-09-23** · Analytics events stored in Firestore with a route-guarded internal dashboard, not GA4. · SPEC §3 asks only for a tiny internal dashboard; keeps the retention gates queryable and off a third party.
- **2026-09-23** · Email in P0 is a skeleton behind a pluggable sender with a console provider; no live sending. · SENDGRID_API_KEY is unset and P0 has no audience to email yet.
- **2026-09-23** · Life Firestore data lives under `households/{id}` per SPEC §7, replacing the `life_members/{uid}` namespace named the previous day. · SPEC is the contract; nothing had been written yet, so the change cost nothing.
- **2026-09-23** · Firestore rules for Life ship as an additive block, proven against the emulator, and are deployed only on Conor's explicit word after he sees the diff. · `firestore.rules` is a single shared file protecting the live underwriting app; there is no way to deploy a Life block without redeploying all of it.
- **2026-09-23** · Signed-out reads localStorage, signed-in reads Firestore; never both. Import clears the local copy only after the write lands. · One source of truth per state avoids two diverging copies of a pet; clearing early would lose the only copy if the write failed.
- **2026-09-23** · Sign-in links are detected by a pure string test on `mode`+`oobCode` before the SDK loads. · `isSignInWithEmailLink()` lives in the SDK, so using it would load ~46KB on every page view just to say "no" to every visitor who is not mid-sign-in — including the investor demo.
- **2026-09-23** · Build typechecks with `tsc -b`, not `tsc --noEmit`. · `tsconfig.json` is a solution file with `"files": []`; the `--noEmit` form checked nothing and had been passing vacuously, hiding 14 errors including one that predated this branch.
